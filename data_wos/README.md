# 출장 일정 - 에이전트는 사람이 안 해도 되는 판단만 대신한다

오늘 이 폴더는 **읽는 재료**입니다. 코드는 어제 만든 booking-hub(React + Vite + Supabase)에서 Haiku에게 말로 시킵니다. 여기 있는 파일을 실행하지 않습니다.

## 오늘의 문장

에이전트가 사람 대신 일을 해 주는 것은 불가능할 때가 많습니다. 에이전트는 **사람이 안 해도 되는 판단**을 대신합니다.

| 경우 | 에이전트 | 카페로 치면 |
|---|---|---|
| 가능한 경우의 수가 1개 | 자동 | "똑같은 걸로 +1" |
| 여러 개인데 차이가 없음 | 자동 (아무거나) | "아무 사이즈나" |
| 아예 없음 | 통보하고 멈춤 | "지금은 품절인데요" |
| 여러 개인데 차이가 있음 | **사람에게 묻는다** (오늘) / 선호로 예측 (월요일부터) | "캔커피 vs 오렌지주스" |
| 사실을 모름 (빈 칸) | 사실을 묻는다 - 결정이 아님 | "몇 잔이요?" |

## 파일

| 파일 | 무엇 | 언제 |
|---|---|---|
| `시나리오_카드.md` | 카드 40장. 카드마다 두 줄을 적습니다 - 혼자 해도 되나 + 앱이 할 일 | 오전 1부(1-20), 오후 2부(21-40) |
| `STATE_출장일정.md` | 컨설턴트의 요구 24칸과 리소스 10칸의 정의. Haiku에게 칸 이름을 말할 때 봅니다 | 필요할 때 |
| `wos_장소택시_샘플20.md` | 지난주 대화 20건. 오전 10분 리마인드용 | 10:00 |
| `wos_장소택시_all.md` / `.jsonl` | 전량 1,297건. 오늘은 안 봅니다 | - |

## 오늘 순서 한 줄

어제 앱 열기 -> 판정 1(빈 칸이면 저장 막기, 어제 준비된 프롬프트) -> 카드 1부 기획 -> 리소스 상수 3줄(프롬프트 A) -> 판정 2(사람이 정해야 하나, 프롬프트 B) -> 카드 2부 3장을 앱과 대조 -> 자기 일정 1건 -> 스크럼.

프롬프트 넷은 `프롬프트.md` 에 있습니다. 순서대로 하나씩 붙여넣습니다.

## 정지선

앱은 "여러 개인데 차이 있음"에서 반드시 멈춥니다. 추천하지 않습니다. 고르는 것은 여러분입니다. 월요일부터 예측을 시작합니다.
